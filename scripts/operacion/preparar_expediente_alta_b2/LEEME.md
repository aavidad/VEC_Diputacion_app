# Preparar un expediente para el alta B2

`preparar.sh --comprobar` consulta las dependencias del servidor y de PostgreSQL en una transacción de solo lectura. Indica qué existe y qué falta. No crea estado ni envía actos de negocio. Comprueba los cuatro certificados mTLS, la CA, el lanzador con `VEC_PERSONAL_B2_GOBIERNO_ENABLED=true`, el ajuste privado `personal_b2.cese_fecha_efecto`, las ocho entradas publicadas de régimen y modalidad, y la RPT del centro 520. Si falta un catálogo, imprime el comando con el JSON del repositorio y una clave UUID guardada en un fichero privado antes del POST. La comprobación solo muestra ese comando; el operador decide cuándo ejecutarlo por el circuito autorizado.

`preparar.sh --aplicar PREPARA-ALTA-B2` prepara **un expediente nuevo** con actores distintos de centro solicitante, ratificador, RRHH e Intervención. Deja la resolución CT registrada y verifica que el GET del plan B2 ofrece la plaza. RRHH debe pulsar después el alta en Personal. Este guion no da de alta, cesa ni incorpora a nadie.

Si faltan el flag o `personal_b2.cese_fecha_efecto`, `--comprobar` muestra comandos manuales para ajustar únicamente esos valores en ficheros privados. No ejecuta esos comandos. `primer_dia_sin_relacion` es el valor del escenario inventado ya ensayado; la duda 140 sobre la fecha de efecto real sigue pendiente y debe resolverse antes de aplicarla a otro caso.

El estado se guarda fuera de Git en `--estado`, con permisos 0600. Cada cuerpo y clave se escriben antes del POST; ante un corte, ejecute de nuevo el mismo comando y el guion recuperará la misma operación. No borre ni copie el estado para reintentar. El bloqueo del fichero impide dos ejecuciones simultáneas. Los parámetros por defecto corresponden a cidonia OpenClaw; para un clon local cambie `--origen`, `--material`, `--config`, `--estado`, `--motor` y `--contenedor`. El lanzador se busca junto al directorio `material` y se puede indicar con `--launcher`.

Si falta la RPT histórica compatible, `--aplicar` añade al **clon sintético autorizado** las seis filas acotadas de unidad, tipo, dotación, puesto, plaza y vínculo. Son datos ficticios de preparación, no una publicación institucional. `fixture_firma.sql` inserta dos precondiciones ficticias de remisión; ninguna es firma electrónica. `fixture_anclaje.sql` une la apertura original de Bolsa del nuevo llamamiento a un candidato CTX sintético existente. La desactivación de triggers de réplica se limita a esa transacción de datos B67/B68; no se altera código, funciones, ACL ni otros expedientes.

Para diagnosticar sin seguir todo el recorrido se admite `--hasta alta`, `--hasta informe` o `--hasta fiscalizacion`. Esos puntos dejan el mismo estado privado para continuar luego con `--hasta resolucion`. Un `FALTA` conserva el cuerpo y la clave del último intento; el operador debe revisar la causa antes de repetirlo. Una ejecución posterior recupera el plan por GET. Si ese GET responde 409, el guion informa `FALTA` y no repite ningún POST.
